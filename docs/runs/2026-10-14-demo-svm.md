The details that had to match: `lowercase`, `char_wb` padding with one space on each side, n-grams cut by characters (code points, not UTF-16 units), the break-out for short words, the white-space set of Python's `str.split()` (includes U+001C to U+001F and U+0085, excludes U+FEFF; JavaScript's `\s` is the reverse, so the class is spelled out), sub-linear tf for the character vectorizer only, a separate L2 norm per vectorizer, coefficient order (word features first), and the smoothed idf `ln((1 + n) / (1 + df)) + 1`, which is rebuilt in the browser from integer document frequencies (the export checks that the rebuild equals scikit-learn's idf to 1e-12).

The size is held down by storing document frequencies instead of idf values and coefficients rounded to 6 decimals (rounding moves decision values by at most 2.1e-6). A test fails if the gzipped model grows past 450 KB.
